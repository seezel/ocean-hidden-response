## Interface

Python: `fit_trend(records, variable, *, start=None, end=None)`, `compare_trends(eep_records, nwp_records, *, start=None, end=None)`. JavaScript: `fitTrend(records, variable, options={})`, `compareTrends(eepRecords, nwpRecords, options={})`. A record is `{month: 'YYYY-MM', value: number|null, coverage: number}`. Variables are `chlor_a` and `sst`. Reject malformed/duplicate months and non-finite values; missing months remain calendar gaps. Negative/zero chlorophyll are invalid observations, never log inputs. Invalid selections return unavailable results with reasons, not stale statistics. Do not mutate records.

Return a JSON-serializable object with `eligible`, `reason` (null when eligible), `n`, `start`, `end`, `slopePerYear`, `trendPerDecade`, `ci95` (two values in the same per-decade units), `pValue`, `df`, `lag`, `baseline`, `absoluteChangePerDecade`, `fitted` (month and fitted value), and `diagnostics`. Unavailable inferential numeric fields must be null. Include `modelVersion` identifying the exact conventions. `trendPerDecade` is chlorophyll percent per decade or SST degrees Celsius per decade. `baseline` for chlorophyll is the geometric mean of eligible observations in the first twelve calendar months of the requested window; absoluteChangePerDecade is that baseline times (exp(10*beta)-1), in mg/m3, explicitly a baseline-anchored transformation, not an absolute linear slope. For comparison use aligned positive months and the difference of log EEP minus log NWP. Report comparison `slopePerYear` and `ci95` on LOG-SCALE PER YEAR, `trendPerDecade` as 100*(exp(10*beta)-1) describing relative growth-rate ratio. `baseline` and `absoluteChangePerDecade` are null for comparison. Include `estimand` and an explicit unit.

## Model decisions, fixed before observational results

- Monthly OLS: intercept, continuous calendar time in years, and eleven month-of-year indicators with January omitted. Chlorophyll response log(value), SST response value.
- Eligibility: requested span at least 120 calendar months, at least 120 valid months, completeness at least 0.85, at least five observations for each calendar month, no missing run over six months, and full-rank model. Treat coverage below 0.1 as missing; retain 0.1+ records. Label all these minimums as conservative project policy, not universal statistical guarantees.
- Newey-West/Bartlett HAC covariance with lag floor(4*(n/100)^(2/9)), at least 1. Preserve calendar spacing: sum score cross-products only for pairs separated by the relevant calendar lag. Use small-sample n/(n-k) correction, k=13. Use Student t distribution with n-k degrees of freedom for two-sided p and 95% CI; document that HAC inference remains approximate.
- Diagnose residual lag-1 autocorrelation, standardized residual scale, condition/rank failure and lag sensitivity at 6, 12, and 24 months. Report sensitivity CIs and whether significance conclusion changes. Do not silently select the best lag. Endpoint sensitivity and longer-dependence caveats may be documented, but never claim causation.
- Stable numeric linear algebra. Solve centered/scaled design via QR or validated inversion with conditioning checks; JavaScript is independent implementation, Python may use numpy/statsmodels. SciPy provides t distribution oracle. Independently compare complete-month cases with statsmodels OLS/HAC under identical correction and lag; missing-calendar cases need independent check preserving calendar lags.
- Python and JavaScript must agree within 1e-8 absolute for slope/SE and 1e-6 for p/CI (allow documented relative tolerance on large-magnitude cases). Test positive, negative, zero, seasonal, autocorrelated, missing-month, too-short, singular, invalid chlorophyll, and paired regional series. Include a case where different individual p-values do not establish a significant regional difference.
